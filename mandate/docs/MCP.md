# Mandate MCP server

This is a thin Streamable HTTP MCP client of the Mandate gateway. It exposes only
catalog discovery, purchase proposals and purchase status. The gateway owns policy,
reservations, approvals, payment execution and evidence; this server has no payment
authority and never imports the core ledger or rail services.

## Run locally

From `mandate`, install `backend/requirements.txt` in your virtual environment.
Start the gateway separately, explicitly choosing its mode. For local sandbox use:

```powershell
$env:MANDATE_MODE = "sandbox"
py -m uvicorn backend.api.main:app --host 127.0.0.1 --port 8000
```

Production configuration is validated by the gateway; do not use sandbox settings
for real money. Issue an agent session key using the gateway's existing owner
workflow. Do not give the MCP server an owner token or payment credentials.

In another terminal, from `mandate`:

```powershell
py -m backend.mcp_server
```

The endpoint is `http://127.0.0.1:8765/mcp`. It uses the official `mcp` Python SDK
within major version 1. No key is needed in the MCP process environment: clients
send their own agent capability on every request.

| Environment variable | Default |
| --- | --- |
| MANDATE_GATEWAY_URL | http://127.0.0.1:8000 |
| MANDATE_MCP_HOST | 127.0.0.1 |
| MANDATE_MCP_PORT | 8765 |
| MANDATE_MCP_ALLOWED_ORIGINS | Empty; comma-separated exact browser origins |

The MCP process does not load `.env` automatically. Configure its environment
explicitly. Every gateway HTTP call has a ten-second timeout, with redirects and
automatic retries disabled. HTTP access logging is disabled by the entry point.

## Tools

All schemas reject unknown fields. `catalog()` has no arguments.
`purchase_status(purchase_id)` reads a gateway purchase ID.
`propose_purchase` requires seller_domain, seller_address, item, amount and
request_key; arguments is an optional JSON object. Amount is a decimal string such
as `"0.040"`, never a float. The request key is supplied by the agent, 8–128
characters, and must stay unchanged for the same proposal. No key is generated by
this server.

Arguments permit at most 20 object keys in total across nested objects, string
values of at most 500 characters, and three container levels counting the root
object as level one. Nested arrays also consume a container level. Non-finite
numbers are rejected. Arguments are sent as tool_call.arguments with tool name
propose_purchase; changing them changes the gateway's idempotency envelope.

Gateway fields such as id, stage, decision, clause and amount are returned without
conversion. PENDING_APPROVAL includes guidance to seek a person's approval in
Mandate and not retry. BLOCKED retains the gateway clause. Gateway 401/403 produces
the tool error `session key missing, frozen or revoked`; 409/422 retains its detail.
Other unavailable or malformed responses never claim success.

## Timeouts and retries

The MCP server makes exactly one HTTP call for a proposal. If it times out or the
network fails, it returns outcome `unknown`, the original request_key, and:

> The outcome is unknown. To check it, call propose_purchase again with EXACTLY the same request_key and the same arguments. Mandate is idempotent on request_key: it returns the existing purchase, or creates it once if the first call never arrived; it never creates a second purchase. Do not change any argument and do not use a new request_key. If it still fails, stop and tell the owner, quoting the request_key.

This is an explicit subsequent agent call, never an automatic retry inside the
server. Once a purchase ID is known, use purchase_status for observation. An owner
must resolve payment/approval uncertainty in Mandate. Do not bypass an UNKNOWN
outcome with a new request key or changed inputs.

## Connect Grok

Remote xAI servers cannot reach your laptop's loopback address. Deploy behind a
reachable HTTPS reverse proxy, keeping the upstream bound to loopback, and pass
Authorization through without logging it. Keep credentials out of URLs and proxy
access logs. Do not expose the plain local HTTP listener directly to the internet.

In an xAI Remote MCP tool configuration, use the public HTTPS `/mcp` URL and the
agent credential from your client's private environment:

```python
import os

mandate_tool = {
    "type": "mcp",
    "server_label": "mandate",
    "server_url": os.environ["MANDATE_PUBLIC_MCP_URL"],
    "headers": {"Authorization": "Bearer " + os.environ["MANDATE_AGENT_KEY"]},
    "allowed_tools": ["catalog", "propose_purchase", "purchase_status"],
}
```

Use this object in the tools array of the xAI Responses request. xAI also documents
an `authorization` parameter; the explicit header above avoids ambiguity about
the Bearer prefix. Native xAI SDKs name the header option extra_headers. See
[xAI Remote MCP documentation](https://docs.x.ai/developers/tools/remote-mcp).

## Connect Claude or another MCP client

Use a client supporting Streamable HTTP and custom Authorization headers. Configure
the `/mcp` URL, transport Streamable HTTP, and `Authorization: Bearer <agent key>`
through its private credential facility. In Claude Code, an HTTP MCP entry has this
shape; substitute the credential privately, never commit a populated config:

```json
{
  "mcpServers": {
    "mandate": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": {"Authorization": "Bearer <MANDATE_AGENT_SESSION_KEY>"}
    }
  }
}
```

Client configuration formats vary. Clients that require OAuth discovery or cannot
supply a bearer header need their own compatible integration; this server does
not implement an OAuth authorization server or promise universal client support.
See the [Claude Code MCP reference](https://code.claude.com/docs/en/mcp) for client
configuration and private environment-variable expansion.

## Security and verification

The key has only the gateway's configured agent/mandate authority. The owner can
freeze or revoke it in Mandate. The MCP adapter cannot approve, unpause, change
policy, issue capabilities or directly call a rail. Keys are request-local: never
stored in application configuration, cached between callers, echoed or logged.

Origin is validated on every request, including unknown routes and HTTP methods.
Missing Origin is permitted for non-browser clients; any present Origin must
exactly match the configured list. The default empty list rejects every browser
origin, including `null`. Origin checks do not replace bearer authentication or
HTTPS. Browser cross-origin preflight/CORS support is not provided by this server.

From `mandate`, before committing:

```text
py -m pytest -q
py -m ruff check backend scripts
py scripts\smoke.py
```

Tests use the real gateway through in-process ASGI HTTP with sandbox integrations,
plus synthetic transport failures. They make no real network or payment calls.
